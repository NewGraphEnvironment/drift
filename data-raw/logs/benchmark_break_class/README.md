# benchmark_break_class — dft_rast_break_class() on the BULK floodplain (drift#9)

Produced by `data-raw/benchmark_break_class_bulk.R` on 2026-09-05 (64 GB machine, terra
1.9.34). AOI: the `co_ff04` layer of `bulk_co_ff04/floodplain.gpkg` from stac-floodplains-bc
(386.5 km²). IO LULC 2017-2023 fetched from Planetary Computer with
`dft_stac_fetch(tile_size = 20000)` — 30 tiles per year, 1,414 s for the seven — onto a
16000 x 12000 grid at 10 m (192M cells, EPSG:32609). The STAC item itself carries only
`classified_2017/2020/2023`.

Committed evidence (the `.log`, `.tif` and `.gpkg` files are gitignored):

- `summary_pixels.csv` — `res$summary`: area by transition, status and break year
- `summary_change.csv` — endpoint-changed pixels by temporal category (sustained break /
  endpoint break / flicker) and the stable-endpoint flicker
- `summary_patch_groups.csv` — the per-patch temporal evidence (`summary_patches.csv`, 21,710
  rows, regenerated by the script and not committed) summarised by geometric signature; the
  numbers `NEWS.md` quotes
- `timings.csv`, `run_wallclock.txt`, `rss_run.txt` (RSS in KiB every 2 s) — the final run,
  on the script and code as committed (peak 20.9 GiB)

Four runs were made as the memory fixes landed (see the archived planning `findings.md`):
run 1 stalled in the script's own `cat_fun`, which tolerated a bare vector and so ran once
per cell — the same defect review round 1 found in the function; run 2 (pre-spill code)
peaked at 21.3 GiB; run 3 measured the spill; the committed run 4 numbers are in `timings.csv`. The function's own
footprint was separated from the 8.5-20 GB the seven in-memory inputs cost the caller with
the scratch probes described in `findings.md`: ~10 GB from a 0.3 GB file-backed floor at
9.6M-cell chunks, the crosstab flat at 7 GB.

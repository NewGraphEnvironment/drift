# break_class_groups — dft_rast_break_class() across four watershed groups (drift#62)

Produced by `data-raw/break_class_groups.R` through `data-raw/break_class_groups-run.sh` on
2026-09-05 (m1, 64 GB, terra 1.9.34, drift 0.14.0). Inputs are the seven `classified_<year>`
COGs each item publishes on stac-floodplains-bc — the four items that carry every IO LULC year
2017-2023: `bulk_co_ff04`, `necr_ch_ff04`, `lnth_ch_ff04`, `kotl_bt_ff04`. PINE was dropped
upstream (floodplains#76). Every download was verified against the asset's `file:checksum`.
The COGs are already clipped to the floodplain, so there is no fetch and no AOI mask; they are
file-backed, so the 8.5-20 GB in-memory input floor the #9 BULK run carried is gone.

Committed evidence (the `.tif`, `.gpkg`, `.json`, `.log` files and each group's
`summary_patches.csv` are gitignored and regenerated by the script):

- `<group>/group_meta.csv` — grid, CRS, cell counts, run date, package versions
- `<group>/summary_class_freq.csv` — cells per class per year (clouds; equal valid cells per year)
- `<group>/summary_pixels.csv` — `res$summary`: area by transition, status and break year
- `<group>/summary_break_year.csv` — clean-break area by `break_year` (Q2)
- `<group>/summary_change.csv` — endpoint-changed pixels by temporal category (Q1)
- `<group>/summary_patch_groups.csv` — per-patch temporal evidence by #44 geometric signature (Q4)
- `<group>/summary_shape.csv` — ff02 / ff04 / ff06 area, perimeter, polygon count, `2A/P` width (Q3)
- `<group>/timings.csv`, `rss.txt` (RSS in KiB every 2 s), `run_wallclock.txt`
- `summary_groups.csv` / `summary_groups.md` — one row per group, assembled by the `summarize`
  stage; the `.md` is what `inst/notes/temporal-qa-groups.md` includes verbatim
- `summary_bulk_reconcile.csv` — BULK on the published grid (14651 x 11552) against the #9
  run on the grid `dft_stac_fetch()` tiled from Planetary Computer (16000 x 12000)

The `summarize` stage also writes the pkgdown article's tables into
`inst/extdata/temporal-composition/` (drift#66), described in that directory's own README. They
are a rollup of the committed `summary_pixels.csv` files, guarded against each group's
`summary_change.csv` on integer cell counts, so they cannot drift from the numbers above.

Runs, in order: bulk 312 s / 15.4 GiB peak, kotl 323 s / 16.3 GiB, lnth 100 s / 13.7 GiB, necr
138 s / 14.2 GiB. Peak RSS sits at 14-16 GiB whatever the grid size (56M to 204M cells), so it
is terra sizing its working set against available RAM rather than a per-group requirement —
the same observation floodplains#79 made. The transition-artifact stage is the largest
share of every run (44-58% of wall, `timings.csv`).

necr ran once before the batch, as the shakedown of the script; that run's `rss.txt` sampled
the wrapper shell (a `cmd && Rscript … &` backgrounds the whole list, so `$!` was not R) and was
discarded. The launcher starts `Rscript` alone so the sampled PID is R's. Edits to the
script after the batch, all in code the per-group stage does not run or in an error path: the
checksum-mismatch message (it now also removes the cached `item.json`); in the summarize stage,
the note-verbatim guard moved after the reconcile write, `overstatement_factor` derived from the
unrounded sustained area, `stable_flicker_over_changed` added, and the reconciliation rows built
unrounded and rounded once. The summarize stage was re-run after each; no per-group number moved.

Q3 was first designed around the per-stream `<sp>_ff04_by_blue_line_key` layer and dropped
before the run: its polygons overlap 1.7-2.2x (tributary floodplains nest inside the
mainstem's), `valley` is constant, and kotl has no such layer. `summary_shape.csv` is what
replaced it.

Two ratios in `summary_groups.csv` — `ff06_over_ff02` and `pct_area_artifact` — divide areas the
per-group stage wrote rounded (2 dp km², 1 dp ha). Recomputed from the unrounded sources, all
eight cells are unchanged; carry an unrounded column the next time the per-group stage runs.
